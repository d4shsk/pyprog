Расширить функциональность веб-приложения, реализовав полноценное взаимодействие с базой данных.
**Основные задачи:**

### 2. Описание предметной области

В базу данных были перенесены следующие сущности и связи:

1. **User (Пользователь)**
* `id`: `INTEGER PRIMARY KEY AUTOINCREMENT` — уникальный идентификатор.
* `name`: `TEXT` — имя пользователя.


2. **Currency (Валюта)**
* `id`: `INTEGER PRIMARY KEY AUTOINCREMENT`.
* `char_code`: `TEXT` — символьный код (USD, EUR).
* `name`: `TEXT` — название.
* `value`: `REAL` — текущий курс.
* `nominal`: `INTEGER`.


3. **UserCurrency (Связь «Много-ко-многим»)**
* Таблица связывает пользователей и валюты.
* `user_id`: `INTEGER` (Внешний ключ -> `user.id`).
* `currency_id`: `INTEGER` (Внешний ключ -> `currency.id`).

### 4. Реализация CRUD и SQL-запросы

Взаимодействие с БД инкапсулировано в классе `DatabaseController`. Для безопасности используются параметризованные запросы (значения передаются через кортеж параметров, а в SQL ставится знак `?`).

#### Create (Создание)

Используется при заполнении базы начальными данными (`seed_db`).

```python
sql = "INSERT INTO currency(num_code, char_code, name, value, nominal) VALUES(?, ?, ?, ?, ?)"
self.cursor.execute(sql, ('840', 'USD', 'Доллар', 90.5, 1))

```

#### Read (Чтение)

Получение списка всех валют или поиск по ID.

```python
# Получение всех записей
self.cursor.execute("SELECT * FROM currency")
rows = self.cursor.fetchall()
# Преобразование кортежей ответа БД в объекты модели Currency
return [Currency(*row) for row in rows]

```

#### Update (Обновление)

Изменение курса валюты.

```python
sql = "UPDATE currency SET value = ? WHERE char_code = ?"
self.cursor.execute(sql, (new_value, char_code))
self.conn.commit()

```

#### Delete (Удаление)

Удаление записи по первичному ключу.

```python
sql = "DELETE FROM currency WHERE id = ?"
self.cursor.execute(sql, (currency_id,))
self.conn.commit()

```

### 6. Тестирование (unittest.mock)

В данной работе применено тестирование с использованием «моков» (заглушек). Это позволяет тестировать `CurrenciesController` изолированно, не создавая реальное подключение к базе данных.

**Пример теста (`tests/test_mock.py`):**

```python
def test_get_currencies_context(self):
    # 1. Создаем Mock (имитацию) базы данных
    mock_db = MagicMock()
    
    # 2. Задаем поведение: метод БД должен вернуть подготовленный список
    fake_list = [Currency(1, "840", "USD", "Test Dollar", 90.0, 1)]
    mock_db.get_all_currencies.return_value = fake_list
    
    # 3. Передаем Mock в контроллер вместо реальной БД
    controller = CurrenciesController(mock_db)
    context = controller.get_currencies_context()
    
    # 4. Проверяем, что контроллер вернул данные из нашего фейкового списка
    self.assertEqual(context['currencies'][0].char_code, "USD")
    # Проверяем, что контроллер действительно обращался к БД
    mock_db.get_all_currencies.assert_called_once()

```

Тесты прошли успешно, подтверждая корректность логики контроллера.

### 7. Выводы

В ходе лабораторной работы №8 были успешно решены задачи по интеграции базы данных в веб-приложение на Python.

1. **MVC и разделение ответственности:** Выделение `DatabaseController` позволило убрать SQL-код из бизнес-логики. Контроллеры страниц (`CurrenciesController`) теперь просто запрашивают данные у слоя БД, не зная о деталях реализации SQL.
2. **Работа с SQLite:** Использование базы данных в памяти (`:memory:`) оказалось удобным для разработки и тестирования, так как база всегда чистая при перезапуске сервера.
3. **Безопасность:** Использование параметризованных запросов (`?`) защищает приложение от внедрения вредоносного SQL-кода.
4. **Маршрутизация:** Реализована обработка действий (удаление) через GET-параметры с последующим перенаправлением (`self.send_response(303)`), что улучшает пользовательский опыт.
5. **Тестирование:** Освоена библиотека `unittest.mock`. Она позволила протестировать логику контроллера без необходимости поднимать реальную базу данных, что делает тесты быстрыми и независимыми.
